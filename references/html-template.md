# 默认 HTML 周报模板

用户已选定原版周报的布局作为默认样式。生成 HTML 时直接复用 `assets/weekly-report.html`，不要另起一套仪表盘布局。用户指定其它模板或局部调整时，以当次要求为准。

## 固定版式与可变内容

- 米白背景、细分隔线、宽留白；顶部 RESEARCH / WEEKLY 导航。
- 左侧姓名大标题，右侧日期；姓名未提供时显示“学术周报”。日期与工时使用 Arial，姓名保留原版衬线风格。
- 顶部为全周和每日用时总览；不具备计时依据时隐藏，不虚构时间。
- 最多三张重点任务卡片，每张有短要点及项目用时；优先用户指定重点，否则有时间数据时按可记录投入排序。少于三项时不凑数。
- 每日投入堆积图遵循 [html-charts.md](html-charts.md)，采用独立的图表配色，不改变项目卡片和甘特表的柔和配色。
- **每日活动区是项目×日期甘特表，每格保留1—3条简短动作，并在有时间数据时附该格合计。不能替换为只有数字的工时表。** 多个动作共享项目日时间，不给每个动作复制整格时长。
- 项目详情采用原生 `<details>` 折叠，含按日进展、产出状态和下一步；不要默认展开成大量长卡片。
- 页底集中放记录说明。Obsidian按钮仅在真实文件归档并核验链接后提供，模板不预置知识库路径。

## 文件与生成方法

- `assets/weekly-report.html`：保留原版CSS和布局，使用命名插槽；无姓名、真实项目、旧日期、旧工时和私人路径。
- `assets/example-data.json`：纯虚构排版示例，不能当作真实周报证据。
- `scripts/render_report.py`：Python标准库生成器。根据同一份项目日数据生成独立HTML和CSV，支持未知工时和缺失日期；不执行工时推断。

以技能目录为当前目录运行（输出位置使用本次用户指定目录）：

```sh
python scripts/render_report.py report-data.json output/report.html
```

先把已筛选、有来源的内容写成JSON，再生成报告。原始证据与逐窗口估算依据保存在本次私人输出目录，不写入技能。需要Markdown或Obsidian归档时，使用同一份JSON另生成Markdown，保持内容与状态一致。

## 数据约定

参考虚构示例组织数据：

- `author`：可省略，不从账户名猜测。
- `start`、`end`：ISO自然日，均包含；`timezone`为已确认时区。
- `time_mode`：`none`不展示用时；`estimated`为用户接受且有证据的估算；`measured`为可核实计时。不要把两种口径混为实测。
- `partial`：记录不完整时为`true`，顶部显示“可估算部分合计/已记录部分合计”。
- `missing_dates`：记录缺失日期数组；这些日期不得输入分钟值。不完整时段另在`notes`交代。
- `notes`：日期范围、覆盖、来源、估算假设及局限的简短说明。不写生成过程或实现要求。
- `obsidian_url`：可选，仅接收已验证的`obsidian://open?...`链接。
- `projects`：每项有稳定`id`、`name`、`highlights`（最多三项）、可选`featured`、`outcome`、`next`、`paper_title`及`days`。
- `days`：每条含`date`、`actions`（1—3条简短动作）、`detail`、`minutes`。`minutes`以非负整分钟输入，上游保留取整前依据；用时未知用`null`或省略；明确计时为零才用`0`。无该项活动证据时省略该项目日条目，不能补出连续工作日期。
- `next`中的推导行动写明“建议”；审稿使用已核实完整稿名，未知则注明待核实。

生成器只加总输入，不通过关键词、摘要条数或日期跨度猜工时。上游须先去重、处理跨午夜和多项目窗口，保留未取整依据；不要沿用旧周报的总时长或将所有微小片段向上取整。

## 交付检查

打开生成的确切HTML，检查顶部、重点任务、堆积图、含动作的甘特表和折叠详情。检查小屏横向滚动、较长项目名和缺失值，核对CSV、每日、项目和全周合计一致。全部无时间数据时仍交付活动报告，隐藏用时总览和时间图。最终直接提供命名的报告文件链接；用户明确要求成稿时不能只返回候选清单。
