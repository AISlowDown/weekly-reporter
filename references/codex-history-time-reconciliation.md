# Codex 对话补查与时间对照

每次周报均执行，范围覆盖报告内所有自然日；即使某日已有 Computer History 记录和估算，也要核对该日 Codex 工作记录。用户明确限制范围时遵循该限制。

## 查找当天实际发生的工作

1. 优先使用可用的任务列表及对话读取工具；需要精确时间与来源时，读取当前用户可访问的本地会话日志。按目标日期限定范围，旧任务可能在目标日期继续工作，不能仅查当天新建任务目录。
2. 以消息、回合和工具事件的实际时间为准，转换为报告时区。文件名、任务创建日、目录日期及文件修改时间不能代替活动日期；跨午夜拆分。
3. 阅读用户的实质请求、连续反馈、对应结果及必要的文件/工具证据。系统注入、环境上下文、心跳、审批代理、后台子代理运行不作为用户活动。续存、分叉和重复消息去重，子任务成果并回所属项目。
4. 按对话内容识别项目；工作目录和任务标题仅为线索。同一对话可能从工具开发转为基金拟题或论文解读，不能把整段对话都归给目录所指项目。
5. 用户请求只证明提出任务；助手完成声明写为“记录中报告完成”。重要产出按需核对工具结果与现存文件。补查若发现后续保存、试验执行或提交结果，应修正旧周报的过时状态；只有原路径失效时，不能抹去有证据的历史交付。
6. 保留来源定位：任务ID、本地时间、消息/回合标识，或日志路径及行号。查到工作后取消“整日记录缺失”，必要时改为“Codex记录补充，覆盖不完整”；没有证据时不推断采集停止、清理或无工作。

## 用户已接受估算时的用时处理

- 将有实质交互的时间放到共同时间轴，与 Computer History 窗口逐一对照。活动内容与时间都可归属时可粗估，不因来源是对话就一律留空。
- 可采用十分钟窗口、五分钟粒度作为与已有周报一致的粗估方式：部分交互通常分配约五分钟；有持续阅读/反馈等证据才分配更长时间，最多为窗口长度。不能把每条消息机械换成五分钟，也不能按关键词次数计时。
- 单纯确认、索取链接、焦点切换等不单独累加。只有助手输出、长时间工具运行或任务完成时间，不足以证明用户持续工作；长间隔不补齐，不把首次至末次发言跨度或AI运行时长算成个人工时。证据不足时保留未知。
- 同一窗口先去重再分配：两种来源证明同一项目时合并，不能相加；不同项目按活动线索分摊。已有前台记录优先于推测性对话时长；若新证据表明原归属有误，修正分配并记录原因。所有项目合计不得超过窗口长度。
- 保留对照明细：窗口本地起止、两类来源定位、原分配、新增或修正分配、合并后项目分钟、判断依据。估算假设明确写入说明，避免制造分钟级实测的印象。
- 重新计算项目日、每日、项目周及全周合计，由同一份合并数据生成图表、HTML、Markdown和CSV。核对重复窗口、跨日归属及合计一致性。
- 更新为命名新版本，保留原报告；将自动化已处理状态指向新版本。交付每日与全周的新估算，并说明仍为覆盖范围内的活动窗口估算，不是完整实际工时。

## 全日期核对完成条件

- 保存逐日核对表：日期、Computer History覆盖范围、Codex实质交互范围、来源可访问性、新增/修正活动、重叠去重情况、更新前后估算。无新增也记录“已核对，无新增”，不能把未查写成无新增。
- 检索应包括报告期之前创建但期内继续的任务及续存日志；按消息事件时间过滤，不能靠文件修改时间排除。检查分叉继承和回放，避免把导入的旧消息重新算作当天活动。
- 所有日期核对完后一次性汇总，检查每日、项目和全周总量一致，以及同窗总分配不超窗口长度。记录检查完成与全天活动完整是两回事；未采集、线下和未访问设备仍可能漏计。
